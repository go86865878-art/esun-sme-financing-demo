# 中小企業資金規劃測試網

首頁聚焦「批發商訂單增加、收款晚於付款」的一個情境，依序完成經營數字、缺口與還款初步檢查、轉交服務需求。

展示網站：https://go86865878-art.github.io/esun-sme-financing-demo/

## 3 分鐘 Demo

1. 首頁按「用示範案例走一次」，按「計算並查看結果」。示範週轉缺口為 619.2 萬元。
2. 按「收款再慢 30 天」，收款由 60 天改成 90 天，缺口為 1,753.4 萬元。
3. 確認用款月份與一年還款餘裕。月份是自行填寫，還款是所填一年可用現金與全部本息的比較；空白或分母為零不判為健康。
4. 按「確認結果，整理服務需求」，選擇地區、勾選希望討論的服務與示範轉交同意。
5. 成功畫面出現案件編號。按「在工作台開啟這筆需求」，工作台直接開啟相同案件，顯示相同缺口、月份與還款檢查。
6. 按「採用路由建議（示範）」完成分派。重新整理後，狀態仍保留。

## 保留的進階功能

`tools.html` 保留原本四種用途、完整財務健檢、月度規劃、文件及知識問答。首頁只保留次要入口，文件清單在結果頁按需展開。工作台的貢獻估算與管理設定改為展開查看。

## 執行與驗證

靜態檔放在儲存庫根目錄，透過 HTTP 開啟，不用安裝前端套件。可執行 `python -m http.server 4177`，再開啟 `http://localhost:4177/`。`npm test` 執行融資模型、健檢、月度收支、摘要、商機及前後台轉交資料測試。

## 示範範圍

- 需求與分派透過同一來源的 localStorage 保存，只在同一瀏覽器可見，不跨裝置同步，不連接銀行系統，也不會發送通知。
- 轉交使用白名單保存試算、月份、還款輸入、服務意願與同意紀錄；還款判讀由原有健檢引擎重算，不採信外部傳入的燈號。
- 工作台以案件編號直接定位；找不到資料會明確提示，不以其他樣本冒充剛才送出的案件。
- 修改試算或轉交內容後須重新計算、確認同意。需求缺口不是可核貸額度；還款初步檢查不是完整財務健檢或信用評分。
- 只使用虛構示範資料，不填姓名、電話、統編或真實員工資料。正式上線仍需身分權限、後端資料庫、CRM 與稽核。
- 原有問答是本機文件知識庫，未串接生成式 AI。文件版本與適用性仍需銀行確認。
